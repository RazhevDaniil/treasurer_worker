# "Retry в AI-агентах" Код требования: RR-AI-5

## Правила разработки и фиксации прогресса
Реализация должна быть применима в любом языке и стеке.

## Правила реализации retry / backoff
  
0. В AI-агентах должны быть установлены retry — ограничения повторных вызовов сервисов при их [временной] недоступности (обращения к другим AI-агентам, LLM, API, сервисам).
1. Retry/backoff реализуется только в общем REST client / infrastructural client.
2. Бизнес-логика, services и nodes не должны вручную повторять запросы.
3. Retry разрешён только для временных ошибок:
   - `httpx.RequestError`
   - HTTP `500`, `502`, `503`, `504`
4. Для `4xx`ошибок по которым retry не нужен (например 408, 429), ошибок валидации, сериализации и бизнес-ошибок retry запрещён.
5. Количество попыток должно быть ограничено через `max_retries`.
6. Между попытками обязателен exponential backoff.
7. Backoff должен иметь `min`, `max`, `multiplier`, при необходимости `jitter`.
8. После последней попытки исходная ошибка должна быть проброшена выше.
9. Нельзя:
   - делать бесконечный retry;
   - писать `except Exception: retry`;
   - дублировать retry-логику в endpoint-методах;
   - проглатывать финальную ошибку.
10. Обязательное логирование:
   - старт попытки;
   - успех попытки;
   - ошибка попытки;
   - ожидание перед следующей попыткой.
11. Логи не должны содержать секреты и чувствительные данные без маскирования.
12. `response_hooks` не должны ломать основной flow при своей ошибке.
13. `error_hook` вызывается только если:
   - ошибка не retryable;
   - или попытки исчерпаны.
14. Все новые REST-клиенты обязаны переиспользовать существующий общий retry/backoff механизм, а не создавать свою реализацию.
15. Любые изменения retryable-ошибок, backoff-параметров или числа попыток должны быть явно обоснованы в коде или описании PR.
 
 
## Что проверять на review
 
- retry находится в инфраструктурном слое;
- retry выполняется только для retryable ошибок;
- есть exponential backoff;
- есть ограничение по попыткам;
- финальная ошибка не теряется;
- логирование полное и единообразное;
- нет копипасты retry-кода.
